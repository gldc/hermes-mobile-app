This file fixes the names and types that cross plan boundaries. **A produces everything below and B
consumes it.** C and P touch none of it. A plan may add private helpers, but it may not rename,
re-type or re-home anything listed here. If a plan-writer finds a listed item impossible, they flag it
in their plan's "Contract deviations" section instead of silently changing it.

Throughout, `N:` means upstream at tag `v2026.9.24`, vendored under `src/vendor/hermes-gateway/`.

## 2. Adapter: `src/api/gatewayClient.ts` (A)

```ts
import type { RpcMethods, GatewayEvent, ServerRequestHandler, ConnectionState } from '@/vendor/hermes-gateway';

export class RpcError extends Error {            // unchanged public shape
  constructor(message: string, readonly code: number);
}

export interface GatewayClientDeps {
  socketFactory: (url: string) => WebSocket;     // today's makeNativeSocket, no Origin header
  requestTimeoutMs?: number;                     // default 120_000 (vendored default)
}

export class GatewayClient {
  constructor(deps: GatewayClientDeps);
  /** Resolves only after socket open AND `gateway.ready` received AND one macrotask tick
   *  (so the channel's `client.capabilities` frame is already on the wire). Rejects on
   *  connect failure/timeout. Callable repeatedly on the same instance (after invalidate()). */
  connect(url: string): Promise<void>;
  /** Drop the current socket (zombie-safe) so the next connect() redials. */
  invalidate(): void;
  close(): void;
  get isOpen(): boolean;
  /** Typed RPC. Unknown param keys are a compile error. Rejections are RpcError
   *  (code from JsonRpcGatewayError.code, or -1 when absent). */
  call<M extends keyof RpcMethods>(
    method: M,
    params: RpcMethods[M]['params'],
  ): Promise<RpcMethods[M]['result']>;
  /** Every backend event (live and legacy). Returns an unsubscriber. */
  onEvent(handler: (event: GatewayEvent) => void): () => void;
  /** Server→client requests. MUST be registered before the first connect(). */
  onRequest(handler: ServerRequestHandler): () => void;
  onState(handler: (state: ConnectionState) => void): () => void;
}
```

- The vendored client is constructed with `replay: false`. Replay is app-orchestrated.
- The legacy approval call `approval.respond` exists in `RpcMethods` at N:, so it is typed too.
- The legacy `approval.request` **event** is not in the N: event map, so A defines its payload in
  `src/api/legacy-approval.ts`:

```ts
export interface LegacyApprovalRequestPayload {       // shape from v2026.8.18 server.py _approval_request_payload
  command: string; description?: string; choices?: string[]; allow_permanent?: boolean;
  allow_session?: boolean; smart_denied?: boolean; tool_name?: string; [k: string]: unknown;
}
export function isLegacyApprovalEvent(e: { type: string }): boolean; // e.type === 'approval.request'
```

## 3. Turn controller: `src/lib/turn-controller.ts` (A creates, B extends)

Pure module with no React Native imports. A implements state and events; B adds the composer-facing
selectors and the request-card reducers listed in §4.

```ts
export type TurnState = 'idle' | 'waiting' | 'streaming' | 'stopping';
export type CompleteStatus = 'complete' | 'error' | 'interrupted';

export interface TurnModel {
  turn: TurnState;
  /** Set when the last turn ended with status 'interrupted'; UI shows "Stopped". */
  lastStatus: CompleteStatus | null;
  requests: RequestCardState[];        // §4 — ordered by arrival, outside transcript items
}

export type TurnAction =
  | { type: 'submit.sent' }                                   // idle -> waiting
  | { type: 'event.message.start'; replayed: boolean }        // any -> streaming
  | { type: 'event.message.complete'; status: CompleteStatus; replayed: boolean } // -> idle
  | { type: 'event.error'; replayed: boolean }                // waiting -> idle; streaming: no-op
  | { type: 'stop.sent' }                                     // waiting|streaming -> stopping
  | { type: 'stop.failed' }                                   // stopping -> streaming
  | { type: 'resume.seeded'; running: boolean }               // true -> streaming, false -> idle
  | { type: 'socket.lost' }                                   // state kept (NOT forced idle)
  | RequestAction;                                            // §4

export function initialTurnModel(): TurnModel;
export function reduceTurn(model: TurnModel, action: TurnAction): TurnModel;
/** Side-effect gate: haptics/one-shot UI only when !replayed. */
export function shouldFireSideEffects(action: TurnAction): boolean;
```

**Composer selectors (B):**

```ts
export type ComposerMode =
  | { kind: 'send'; enabled: boolean }                 // idle
  | { kind: 'stop+steer'; stopEnabled: boolean; steerEnabled: boolean } // waiting/streaming/stopping
export function composerMode(model: TurnModel, hasText: boolean, hasImage: boolean): ComposerMode;
```

## 4. Request cards (A defines the state and routing; B builds the UI and answers)

```ts
export type RequestKind = 'approval' | 'clarify' | 'secure-entry' | 'vault-declined';
export type RequestStatus = 'pending' | 'answering' | 'answered' | 'skipped' | 'cancelled';
export type CancelReason = 'interrupted' | 'timeout' | 'resolved' | 'session_closed' | 'shutdown';

export interface RequestCardState {
  id: string;                    // JSON-RPC server-request id ("srq-…"), or "legacy:<n>" for 0.20.4 approvals
  kind: RequestKind;
  method: string;                // 'approval' | 'clarify' | 'sudo' | 'secret' | 'vault.*'
  params: unknown;               // typed via the helpers below; NEVER holds a secret value
  status: RequestStatus;
  cancelReason?: CancelReason;
  legacy: boolean;               // true = 0.20.4 approval.request event path (FIFO, approval.respond)
  receivedAt: number;            // ms epoch, for countdowns (secret 300s, sudo 120s)
  /** Batch clarify: qid -> locked answer (from replay `answers` or local locks). */
  lockedAnswers?: Record<string, unknown>;
  /** Transcript anchor: key of the last ChatItem at arrival, so the card renders in place. */
  anchorKey: string | null;
}

export type RequestAction =
  | { type: 'request.received'; card: Omit<RequestCardState, 'status'> } // dedupe by id: update, never duplicate
  | { type: 'request.answering'; id: string }
  | { type: 'request.answered'; id: string; skipped?: boolean }         // optimistic (no ack at N:)
  | { type: 'request.failed'; id: string }                              // back to pending
  | { type: 'request.locked'; id: string; qid: string; answer: unknown } // clarify batch
  | { type: 'request.cancelled'; id: string; reason: CancelReason };

export function kindForMethod(method: string): RequestKind | null; // null => not mobile-supported (-32601)
export function cancelLabel(reason: CancelReason): string;          // "Stopped" | "Timed out" | "Answered elsewhere" | "Closed"
```

**The live-object registry.** It lives in A's `src/lib/request-registry.ts`. The reducer holds only
data, so the `respond`/`fail` closures live here:

```ts
export interface RequestRegistry {
  put(req: ServerRequest): void;                 // latest delivery wins (replay re-delivers same id)
  respond(id: string, result: Record<string, unknown>): boolean; // false if unknown id
  fail(id: string, code: number, message: string): boolean;
  drop(id: string): void;
}
export function createRequestRegistry(): RequestRegistry;
```

**The routing rule (A):**

- The `onRequest` handler is registered at construction.
  - `kindForMethod(method) !== null` → `registry.put(req)`, dispatch `request.received`, and return
    `true`.
  - `'vault-declined'` → dispatch the card, call `req.fail(-32601, 'not supported on mobile')`, and
    return `true`.
  - Anything else → return `false`, so the vendored channel auto-answers `-32601`.
- `request.cancel` events → `request.cancelled`, then `registry.drop`.

**Answering helpers (B, in `src/lib/request-answers.ts`):**

```ts
export function approvalResult(choice: 'once'|'session'|'always'|'deny'): ApprovalResult;   // {choice}
export function clarifySingleResult(answer: string): ClarifyResult;                          // {answer}
export function clarifySkipAllResult(): ClarifyResult;                                       // {} (no answers)
export function valueResult(value: string): ValueResult;                                     // {value}
```

**Legacy approvals:** a legacy `approval.request` event creates a card with `legacy:true` and
`id:"legacy:<counter>"`. Answering it calls `gw.call('approval.respond', {session_id, choice})` and uses
the FIFO rule.

## 5. Reconnect orchestrator: `src/lib/reconnect-orchestrator.ts` (A)

```ts
export interface OrchestratorDeps {
  client: Pick<GatewayClient, 'connect' | 'invalidate' | 'call' | 'isOpen'>;
  mintUrl: () => Promise<string>;                          // fresh single-use ticket URL
  storedSessionId: () => string | null;
  resumeParams: () => RpcMethods['session.resume']['params'];
  loadHistory: (storedId: string) => Promise<void>;       // replaces transcript items (not requests)
  dispatch: (a: TurnAction) => void;
  applyReplayedEvent: (e: GatewayEvent) => void;          // same handler as live, with replayed:true
  onLiveSessionId: (liveId: string) => void;
  sleep: (ms: number) => Promise<void>;                    // injected for tests
}
export interface ReconnectOrchestrator {
  /** Single-flight: concurrent triggers join the in-flight run. */
  reconnect(trigger: 'close' | 'heartbeat' | 'foreground' | 'stop-timeout'): Promise<void>;
  /** Live events route through here so they can be parked during steps 2–4 (spec §7). */
  onLiveEvent(e: GatewayEvent): void;
  noteSeq(sessionId: string, seq: number): void;
  dispose(): void;
}
export function createReconnectOrchestrator(deps: OrchestratorDeps): ReconnectOrchestrator;
```

The sequence and rules come from spec §7. `MAX_RECONNECT_ATTEMPTS` and `backoffMs` come from the
existing `src/lib/reconnect.ts`.
