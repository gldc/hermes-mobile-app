Tool Approval from Mobile
Approve or deny dangerous commands from your phone while away from desk
Killer Feature API via WebSocket Medium effort

When the agent needs permission to run a terminal command, write a file outside the project, or execute code — it pauses and waits for approval. Today this only works from the desktop app's inline approval bar. Mobile is the only way to approve when you're away from your desk.

The desktop renders an inline approval component (tool-approval.tsx) with four choices: approve once, approve for session, always approve, or deny. The flow uses WebSocket events (approval.request / approval.response) that already transit the same socket the mobile app uses for chat.

"My agent is running a long task on the server. It hits a dangerous command and pauses. I'm at lunch. Without mobile approval, it's stuck until I get back. With it, I tap approve in 3 seconds and it keeps working." — This is the single highest-value mobile-only interaction that no other AI agent app offers.

Wire Contract
WS ← approval.request (payload: command, risk level, context) WS → approval.response (payload: decision, scope)
2
Gateway Status & Remote Admin
"Is my agent alive?" — status dashboard, start/stop/restart, platform health
API exists Low effort

The most fundamental on-the-go question: is my agent running? A single API call returns gateway state, active session count, connected platforms, exit reasons, and uptime. Start, stop, and restart are one-tap POST requests.

The desktop shows a full gateway boot overlay and messaging platform management view. Mobile could surface a compact status card in the sidebar or settings — green/red indicator, platform chips (Telegram ✓, Discord ✓, Slack ✗), and a restart button.

Self-hosted infrastructure goes down. Tailscale drops, the gateway process crashes, a platform disconnects. Mobile is the fastest way to notice and recover — especially when paired with push notifications for gateway-down events.

Key Endpoints
GET /api/status → gateway_running, active_sessions, gateway_platforms POST /api/gateway/start | /api/gateway/stop | /api/gateway/restart GET /api/messaging/platforms → per-platform connection state GET /api/logs → filterable log stream (level, component, search)
3
Cron Job Full CRUD + Blueprints
Create, edit, pause, trigger, and delete scheduled jobs — browse automation templates
API exists Medium effort

Mobile currently lists cron jobs read-only. The server exposes full lifecycle management: create jobs with schedule + prompt + skills, edit any field, pause/resume, trigger immediate runs, and view run history with per-run session links. A blueprints gallery provides pre-built automation templates (daily briefing, mail monitor, weekly review) that can be instantiated with one tap.

"Did my 9am cron job run successfully?" is a question you ask from your phone. "Pause that job that's burning tokens" is an action you need to take immediately. The blueprint gallery is a discovery experience that's better on mobile — browse templates while on the couch, tap to install.

Key Endpoints
POST /api/cron/jobs — create with schedule, prompt, skills, deliver PUT /api/cron/jobs/{id} — edit any field POST /api/cron/jobs/{id}/pause | /resume | /trigger GET /api/cron/jobs/{id}/runs — run history with session links GET /api/cron/blueprints — browse templates POST /api/cron/blueprints/instantiate — one-tap setup
4
Voice Input & TTS Output
Talk to your agent hands-free — listen to responses while walking or driving
Killer Feature API exists Medium effort

Voice is mobile's #1 differentiator over desktop. The server already runs a speech-to-text pipeline (POST /api/audio/transcribe) that accepts base64 audio and returns transcripts via configured transcription providers. For output, a TTS pipeline (POST /api/audio/speak) supports Edge, OpenAI, and ElevenLabs voices.

The composer gains a microphone button. Tap to record → server transcribes → text appears in the input field for review → send. For responses, a speaker icon reads the agent's reply aloud.

Typing on a phone keyboard is slow. Voice-to-agent is the natural mobile input — tap, speak, send. TTS output turns commute time into productive time: listen to your agent's research summary while driving. No other self-hosted AI agent offers this on mobile.

Key Endpoints
POST /api/audio/transcribe → { transcript, provider } POST /api/audio/speak → base64 audio data GET /api/audio/elevenlabs/voices → voice catalog
5
Usage & Cost Analytics
"How much am I spending?" — daily charts, per-model breakdown, token tracking
API exists Low effort

The server pre-aggregates rich analytics: daily token/cost charts, per-model consumption breakdown, estimated vs actual USD costs, skill usage statistics. The mobile app surfaces none of this today.

A compact analytics view — accessible from the sidebar destinations — would show a 30-day spending trend, today's burn rate, and a model-by-model pie chart. Tapping a model drills into its specific usage pattern.

LLM costs add up silently. "How much did I spend this week?" is a question you ask from your phone when you get a billing alert. The data is already computed server-side — mobile just needs to render it. Budget awareness is a trust-builder for self-hosted AI.

Key Endpoints
GET /api/analytics/usage → daily totals, estimated_cost_usd, token counts GET /api/analytics/models → per-model token/cost/session data
6
Skills Hub
Browse, search, install and manage skills from the community catalog
API exists Medium effort

The server has a full skills marketplace: search the community catalog, preview skill content before installing, install/uninstall with one tap, and toggle skills on/off. Mobile currently shows a read-only skill list.

A hub browser would let users discover new capabilities — "oh, there's a skill for managing Apple Reminders" — and install them without touching the CLI. Skill toggle is a frequent quick action that's perfect for mobile.

Skills are how Hermes grows. Browsing and installing them is a discovery experience that's better on a touchscreen — scroll through categories, tap to preview, swipe to install. Quick toggling ("turn off that skill that's slowing down my prompts") is a 2-second mobile action vs booting the desktop app.

Key Endpoints
GET /api/skills/hub/search?q= → search community catalog GET /api/skills/hub/preview?name= → preview before install POST /api/skills/hub/install | /uninstall PUT /api/skills/toggle → enable/disable a skill GET /api/skills/content → read SKILL.md content
7
Kanban Board
Project management with task CRUD, worker monitoring, and real-time updates
API exists (41 endpoints) High effort

The kanban plugin is a full project management system with 8 columns (triage → todo → scheduled → ready → running → blocked → review → done), task CRUD, comments, attachments, priority labels, multi-board support, and live WebSocket events for real-time board updates. The API has 41 endpoints.

A mobile kanban view would use a horizontal swipe between columns with compact task cards. Tapping a task opens detail with comments and status controls. Worker monitoring shows which AI subagents are actively working on tasks.

Kanban is how power users track their agent's work. Checking board status from your phone — "what's in review? what's blocked?" — is a natural mobile use case. Task comments and quick status changes are 5-second interactions. The API is already exhaustive; the work is purely mobile UI.

Key Endpoints (subset of 41)
GET /api/plugins/kanban/board → columns with tasks POST/PATCH/DELETE /api/plugins/kanban/tasks/{id} POST /api/plugins/kanban/tasks/{id}/comments GET /api/plugins/kanban/workers/active → live AI workers WS /api/plugins/kanban/events → real-time board updates

Session Branching & Undo
Fork conversations into alternate timelines — rollback the last exchange
Partial API Low effort

Three powerful session operations exist as WebSocket RPCs but aren't exposed on mobile: branch (fork a conversation at any point into an alternate timeline), undo (rollback the last user+assistant exchange), and interrupt (stop the agent mid-generation). The desktop has branch support via its session actions menu.

On mobile, these would be swipe actions or long-press menu items on session rows and in the chat header. "Undo" is especially valuable — the agent went off the rails, one tap rolls back to before the last prompt.

"I asked it to refactor and it broke everything. Undo." — Session undo is the kind of safety net that builds confidence in using an AI agent. Branching lets you explore "what if I asked it differently?" without losing the original thread. These are conversation version control — a power feature that's simple to surface.

Wire Contract (WebSocket RPC)
RPC → session.branch { session_id, message_id } RPC → session.undo { session_id } RPC → session.interrupt { session_id }
9
Subagent & Task Monitoring
Real-time status of delegated work — progress, cost, duration, current tool
API via WebSocket Medium effort

When the agent delegates work to subagents (parallel research, code review, multi-step plans), each subagent reports progress through WebSocket events: status transitions, current tool being used, tokens consumed, cost accrued, and completion percentage. The desktop shows this in a rich SubagentProgress panel.

Mobile could surface active subagents as compact progress cards below the composer or in a dedicated "Tasks" view — showing a spinner, current step label, elapsed time, and a cost counter.

You delegate a big task to the agent and walk away. Your phone is the only window into what's happening. "Is it still working? How far along? How much is this costing?" — subagent monitoring answers all three. Combined with push notifications for completion, it turns the phone into a mission control dashboard.

Wire Contract (WebSocket events)
WS ← tool.start { name, subagent_id } — subagent tool invocations WS ← status.update { subagent progress, cost, tokens } WS ← message.complete — subagent finished
10
Session Export & Maintenance
Export conversations, bulk operations, prune old sessions, view stats
API exists Low effort

The server supports full session export (metadata + all messages as JSON), bulk delete (up to 500 sessions), prune by age (older than N days), delete empty sessions, and session statistics (total, archived, message counts, by-source breakdown). None of this is on mobile today.

Export could use the iOS share sheet — send a conversation to Notes, Mail, or Files. Bulk operations would be a multi-select mode in the sidebar. Prune and stats could live in settings.

"Share this conversation with my colleague" — export + share sheet is a 2-tap mobile flow. "Clean up my 400 old sessions" — bulk delete from the sidebar is a quality-of-life feature. "How many sessions do I have?" — stats satisfy curiosity and inform storage decisions. All trivial to build, all useful on mobile.

Key Endpoints
GET /api/sessions/{id}/export → full metadata + messages JSON POST /api/sessions/bulk-delete → { ids: [...] } POST /api/sessions/prune → { older_than_days: 90 } DELETE /api/sessions/empty → remove empty sessions GET /api/sessions/stats → total, archived, by_source
